# Цифровой деканат будущего

Концепт для конкурса, не официальный сервис вуза. Интерфейс и материалы — на русском. Данные студентов вымышленные, преподаватели заменены псевдонимами. Логотипы вуза и сторонние изображения не используются.

Сейчас выполнен этап 0: импорт расписания, обезличенный сид, локальная PostgreSQL PGlite и тесты. Веб-интерфейс, вход и API появятся на следующих этапах. Git используется локально, без удалённого репозитория.

## Запуск этапа 0

Нужен Node.js 20.19+ (проверено на 24.13) и npm.

```bash
npm ci
npm run db:migrate
npm run db:seed
```

База сохраняется в игнорируемой папке data/local-db. Сид содержит группы ТИГ(б)-О-23/1 и ФЭТ(б)-О-23/1 и вымышленных студентов Артёма Тестова и Лину Образцову. Пароли и аутентификация на этапе 0 не создаются. Оба расписания фильтруются по группе, подгруппе, языковым группам и факультативному варианту студента.

Если исходного XLSX нет, db:seed использует data/seed/schedule.json и переносит обезличенные занятия на текущую неделю. Секреты для этапа 0 не требуются. Необязательные пути SCHEDULE_FILE и PGLITE_DATA_DIR можно задать в локальном .env по .env.example; .env исключён из Git.

## Повторный импорт

Поместите исходный XLSX в data/schedule/ или укажите SCHEDULE_FILE в .env. Также поддерживается исходная книга, оставленная пользователем в корне. При нескольких XLSX нужно явно выбрать файл. Источники не включаются в Git, фронтенд или архив сдачи.

```bash
npm run import:schedule
npm run db:seed
```

Первая чётность задаётся единственной константой FIRST_WEEK_PARITY в config/schedule.ts, по умолчанию нечётная. Курс, направление и факультет берутся из шапки. Исторические даты внутри ячеек игнорируются и попадают в отчёт. Весь текст обезличивается до записи в сид или БД. При доле распознавания ниже 95% сид не перезаписывается; обезличенный диагностический отчёт сохраняется.

## Проверки

```bash
npm run lint
npm run typecheck
npm run build
npm test
```

Покрытие тестов: coverage/index.html и coverage/coverage-summary.json. Тесты по оригинальным фамилиям и уникальности всей исходной книги требуют локального XLSX; без него эти проверки явно пропускаются, а синтетические и остальные проверки продолжают работать.

Результаты этапа, метрики и ручная сверка 10 ячеек: [docs/SCHEDULE_IMPORT_REPORT.md](docs/SCHEDULE_IMPORT_REPORT.md). Полный обезличенный машинный отчёт: [docs/reports/schedule-import.json](docs/reports/schedule-import.json).

## Структура

- config/schedule.ts — чётность и выбор демонстрационных подгрупп и языков.
- scripts/import-schedule/ — чтение XLSX, геометрия ячеек, варианты и обезличивание.
- scripts/lib/ — проверка артефактов, перенос дат, БД и студенческая выборка.
- db/migrations/ — совместимая с PostgreSQL схема расписания.
- data/seed/ — переносимый обезличенный сид; data/schedule/ и data/local-db/ локальные.
- tests/ — Vitest, включая интеграцию с PostgreSQL PGlite.
- docs/ и prompts/ — требования, этапы, лицензии и журналы процесса.

Полный стек и оставшийся план заданы в AGENTS.md и docs/PROGRESS.md. Все зависимости, включая транзитивные, записаны в [docs/LICENSES.md](docs/LICENSES.md).
