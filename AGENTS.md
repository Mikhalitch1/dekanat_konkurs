# AGENTS.md — правила проекта «Цифровой деканат»

## Что это
Конкурсный концепт личного кабинета студента МГИМО: расписание, успеваемость, заявки и справки, уведомления, ИИ-помощник, кабинет сотрудника деканата. Не официальный сервис вуза. Интерфейс на русском.

## Стек
- Frontend: React + Vite + TypeScript, PWA (manifest + service worker), CSS-токены из docs/DESIGN.md.
- Backend: Node.js 20+, TypeScript, Fastify, zod.
- БД: PostgreSQL, миграции и сиды в репозитории.
- Деплой: Docker Compose (web, api, db, nginx) на российском VPS, HTTPS.
- Тесты: Vitest (юнит и API), Playwright (e2e, мобильный вьюпорт 360x740).

## Структура
apps/web, apps/api, docs/, prompts/, scripts/, data/schedule/, docker-compose.yml, README.md

## Команды (должны существовать и работать)
npm run dev | build | lint | typecheck | test | e2e | db:migrate | db:seed

## Жёсткие правила
1. Авторизация только на сервере. Идентификатор студента берётся из сессии, никогда из тела запроса или URL. Чужие ресурсы возвращают 404.
2. Пароли только хэшем (argon2id). Ключи и токены только в переменных окружения на сервере.
3. Только вымышленные данные. Имена преподавателей из расписания заменяются псевдонимами.
4. На каждой странице плашка «Концепт для конкурса, не официальный сервис вуза» и подпись команды. Логотип только собственный, без логотипа вуза.
5. Сторонние библиотеки, шрифты, иконки только с разрешающей лицензией, записанной в docs/LICENSES.md.
6. Все основные сценарии работают на экране 360 px.
7. Нет заглушек TODO в готовых экранах. У каждого списка есть пустое состояние, ошибка и загрузка.
8. Офлайн-кэш (PWA) хранит только данные текущего пользователя и полностью очищается при выходе.

## Контрольные точки (без GitHub)
- Репозиторий локальный: git init без удалённого сервера. GitHub не нужен. Если git недоступен, перед каждым этапом копируй проект в папку checkpoints/stage-N (без node_modules) и откатывайся из неё.
- Один этап = одна контрольная точка «stage N: ...». Перед ней: lint, typecheck, test.
- Исходный код для сдачи упаковывается в архив (zip) без node_modules, .env и данных расписания.

## Процесс
- Начинай с этапа 0 (импорт расписания), затем 1–7.
- После этапа обновляй docs/PROGRESS.md (сделано, допущения, что дальше).
- Значимые задачи фиксируй в docs/PROMPTS_LOG.md: этап, цель, суть промта, результат.
- Ошибки: 2 попытки на проблему, затем откат и запись в docs/ERRORS_LOG.md.
- Не меняй файлы вне зоны текущего этапа без причины, указанной в PROGRESS.md.
- Офлайн-расписание (PWA) реализуется на этапе 3, проверяется на этапе 6.

## Definition of Done (этап)
Код собран, тесты зелёные, ручной сценарий из prompts/0N описан и пройден, документация обновлена, контрольная точка создана.

## Агенты и навыки
Codex не запускает кастомных субагентов сам, их нужно вызывать явно. Правила делегирования:
- Backend, БД, API: агент architect_backend.
- Интерфейс и дизайн: агент frontend_designer (навык dekanat-design).
- После каждого этапа с API или авторизацией: security_auditor (только анализ), исправления делает главный агент.
- E2E и мобильные проверки: qa_tester.
- Журналы и описание процесса: process_scribe после каждого этапа.
Параллелить можно только независимые задачи. Задачи, меняющие одни и те же файлы, выполняй последовательно.
Навыки dekanat-design и dekanat-security читай до начала работы с интерфейсом и API соответственно.
Сторонние навыки подключай только после чтения их SKILL.md и скриптов; записывай их в docs/LICENSES.md.
